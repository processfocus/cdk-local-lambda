# AGENTS.md

CLI and CDK Aspect for running Lambda functions locally via an AppSync Events WebSocket relay.

This file is for agentic coding tools working in this repo.

## Essentials

- Package manager: Bun
- Projen-managed repo: edit `.projenrc.ts`, then run `bun run projen` (do not hand-edit generated files)
- Runtime baseline: Node.js 24 (including Docker/Lambda)
- Module system: ESM (`"type": "module"`)
- Lint/format: Biome (not ESLint/Prettier)
- Tests: Bun's built-in test runner (not Jest/Vitest)

## Commands

### Install

```bash
bun install
```

### Build / Compile

```bash
# Full release build (compile + test + lint + package)
bun run build

# Compile TypeScript only
bun run compile
```

### Lint / Format

```bash
# Lint (Biome)
bun run lint

# Lint and apply fixes
bun run lint:fix

# Format (Biome)
bun run format

# Lint a single file (handy for quick feedback)
bunx biome check src/cli/commands/local.ts
```

### Test

```bash
# Run unit tests only (default - fast, no external dependencies)
bun run test

# Run integration tests (requires deployed bootstrap stack)
bun run test:integration

# Run a single test file
bun test test/hello.test.ts

# Run a single test by name/pattern
bun test --test-name-pattern "should transform lambda"

# Watch mode (unit tests only)
bun test --watch test/hello.test.ts

# Coverage
bun test --coverage
```

```bash
bun run deploy:live
```

## Repo Constraints (Must Follow)

- Projen is the source of truth
  - Edit `.projenrc.ts` for tasks/deps/config and re-synthesize with `bun run projen`
  - Generated files contain a header like `// ~~ Generated by projen...`
- ESM import rules
  - Use `.js` extension for relative imports in TypeScript source (emits ESM)
  - Use `node:` prefix for Node.js built-ins (e.g. `node:fs`, `node:path`)
- TypeScript is strict
  - See `tsconfig.json` / `tsconfig.dev.json` (strict, `noUnusedLocals`, `noImplicitReturns`, etc.)
- Formatting is Biome-controlled
  - 2-space indent, 80-column line width, double quotes, trailing commas

## Code Style Guidelines

### Imports

- Prefer explicit, stable import structure:
  - Node built-ins first (`node:`)
  - External deps (Effect, AWS SDK, CDK)
  - Type-only imports (`import type { ... }`)
  - Relative imports last (with `.js` extension)
- Prefer namespace imports for CDK packages (common pattern in this repo):
  - `import * as cdk from "aws-cdk-lib"`
  - `import * as lambda from "aws-cdk-lib/aws-lambda"`

### Naming

- Files: `kebab-case.ts` (e.g. `live-lambda-aspect.ts`)
- Types/interfaces/classes: `PascalCase`
- Values/functions/locals: `camelCase`
- Constants: `UPPER_SNAKE_CASE`

### Types

- Prefer inference for locals, but be explicit at module boundaries:
  - Exported functions/types should have clear signatures
  - Use `import type` for types to avoid runtime import cycles
- Use `satisfies` when you want structure checking without widening types.

### Error Handling

- In Effect-based CLI code (`src/cli/`), model failures with Effect (avoid `throw` in effectful flows).
- When throwing errors (non-Effect code), include context and a stable prefix:
  - Prefer messages like `[LiveLambda] ...` / `[Local] ...` with actionable hints.
- When interacting with external systems (AWS/Docker/child processes), include:
  - the operation, identifiers (function name/stack), and a short next step.

### Logging

- `src/cli/` must use Effect logging (`Effect.logInfo`, `Effect.logDebug`, ...); do not use `console.*` there.
- Outside Effect runtime code, use a clear prefix (`[LiveLambda]`, `[Local]`) and avoid noisy logs.
